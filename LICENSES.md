# Licences for data/

Per-signal terms for everything that lives under `data/`. Code is MIT (`/LICENSE`); this folder is
not. Each file keeps its upstream terms, listed below, and the compilation as a whole is offered
under **CC BY-SA 4.0** because the Wikipedia-derived rows are share-alike (a plain CC BY folder
would be mislicensed). Nothing here is legal advice; every verdict is a reading of the published
terms on the date the evidence quote was captured.

The per-signal table below is generated from `feeds/*.manifest.json` by
`python scripts/gen_data_sources.py` (which also writes `DATA_SOURCES.md`); CI fails if it is out
of date. Edit manifests, not the table.

What each file contains: `data/history/<signal>.csv` is `period, vintage, value, label,
preliminary`, aggregates only. The only labels stored are film titles from Wikipedia (CC BY-SA),
the number-one Netflix film title from the public Top 10 list, the union names on strike days and
the event titles from our own `events.json`, and the index's "N of M components live" note. No headline text, artwork,
per-title Netflix rows or RSS bodies are stored anywhere in this folder. `data/signals.json` and
`data/snapshots/*.json` are derived from the same rows and carry the same terms.

## Legal background, in three sentences

Facts are not copyrightable (Feist v. Rural, 1991): grosses, employment counts and rankings are
facts, and only an original selection or arrangement gets thin protection. The exposure is
contract, not copyright: a public repo that scrapes a site whose terms forbid it is exposed to
breach of contract and to the source closing the tap overnight. There is no database right in the
US, so the pattern is: fetch live with each user's own key where terms allow, commit only derived
aggregates from sources that permit redistribution, and never store rows from sources that do not.
